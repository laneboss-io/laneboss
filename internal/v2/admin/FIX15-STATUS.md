The revoke-reactivation and prepare-false-success control IDs, test selectors
and assertion diagnostics remain. Each now has one edit at the caller's
actual common active-record refusal path. The former makes activation report
the refused lease as active; the latter makes preparation report success
instead of propagating findActive's refusal. Neither test assertion is relaxed.

An unopened revoked data launch preserves the forbidden authorization result
without asking the helper to revoke a nonexistent token. Retained jobs still
run cleanup, and its failure remains visible. Revocation matches a parent's
launch allocation and reservation before a spec is registered. A missing live
gate may use a retained aborted state or exact valid terminal observation;
the population barrier still runs, and missing evidence remains a refusal.

Identity inventory now tracks lane launches from specs and allocations,
capture binding IDs, network lease IDs and network namespace IDs. A lane's
spec may refer to its own allocation; cross-owner aliases and worker/lane
aliases mark every affected owner unusable during recovery. A capture binding
and its own outside lease intentionally share one generated ID and are tracked
once; the positive fixture includes this actual constructor relationship. New workers also
reject retained lane launch IDs. The unrelated-neighbor fixture removes a
copied allocation identity so its existing assertion continues to test an
actually unrelated damaged record.

Native revocation with journal damage inventories the protected installed
cgroup-v2 delegation. Groups belonging to validated allowed owners remain;
every other group receives cgroup.kill before population-zero waits begin.
Stop failures do not suppress later group stops. The returned error reports
stop requests, population failures and retained damage; no damaged journal is
rewritten or UID recycled.

is read. A pathname replacement cannot substitute its mode. Root remains the
production owner requirement; the private descriptor component test uses its
actual file owner and performs real rename/read/mode observations.

tests do not establish cgroup kernel behavior or installed-service acceptance;
