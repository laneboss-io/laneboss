The confined single-source copy and its service consumer have implementations.

These are open dependencies, not claims that the serve acceptance passed.

## Fix 13 checked boundaries

Start/adopt explicitly check the current direct starter's lifecycle state.
Resume/turn check the stored requester against the actual target's strict
starter chain, current ancestor lane and current agent LaunchRecord, including
revocation, identity, run, grant set and policy generation. Original retained
budgets are validated and their disk ceilings apply to source verification.
Current grant lives use the closed lifecycle vocabulary. Terminal delegation
still requires the missing sealed post-exit lease.

Human grants.get still requires a live verified human endpoint and read session
bound to principal, configuration, endpoint generation, absolute expiry and idle
expiry. A template without a Lane additionally requires its immutable service
grants.issued event with the same authenticated human issuer ID. A different
human with a valid session receives not_found and no grant data. Store.Events
must expose that authentic issuance projection for a root life without a Lane;
missing or unreadable issuance authority fails closed. Request params and
caller-selected event payloads do not establish ownership. The in-memory
two-principal control is pending Linux execution, not a native authentication
or security-canary result measured on this Mac.

The worker checks narrow set/data identities, generation, current expiries,
member-to-set and set-to-worker-lease ceilings before copying and before result
acknowledgement. Both new and historical output snapshots must equal the exact
stored source tree, with exact committed artifact metadata for output content.
Source/body paths and all directory components use descriptor-relative
O_NOFOLLOW/O_NONBLOCK opens; source and directory permission handoff also bind
pre-open and opened identities. Home creation is exclusive per component and
the completed home is walked for exact private directories and no extra files.

See SERVE-BACKLOG.md for the installed lifecycle's dependency order and
PROFILES.md for the G3 protected root-profile resolver. Its installed backend
binding and actual protected enrollment remain required. These fixes do not
complete native bootstrap, archive, test, review, channel, publication,
revocation or sealed post-exit lease owners.

## Fix 10 consumer boundaries

Reservations now retain consumed Authority and Level/Role/Driver. Grants selects
those facts only from the stored reservation. It compares the retained original
start/adopt body with them, loads the ticket by Authority.ID, checks the actual
current parent launch for starter authority, and still derives the real parent
grant subset. Human retained proof IDs must match stored proof authority; lane
and root frames cannot borrow a human proof. Actual native authentication and
atomic ticket/proof consumption remain the reservation store's responsibility.

Retained launches require a valid complete previous plan/handoff and matching
agent Kind/Recovery/identity, including the role/level pins. A worker or legacy
missing Kind cannot substitute for an agent. The next reservation, previous
plan and current lane must agree on level/role/driver. Refused outside capture
blocks resume, turn and continuation. Retained materialization replay checks
the plan's D6 capture exception against protected current policy, then opens a
fresh view and checks it again after source/output/journal verification. These
reads do not consume a D6 approval or authorize release; policy/store must
authenticate the actual consumed approval and recheck it under release CAS.

The continuation operation remains the stored reservation's OperationID, never
the intent ID. An unopened continuation cannot present a succeeded operation.
The fixture's pending intent and swap share that operation and pass the shared
validator. The LaunchReservation selector has no ContinuationIntent ID; grants
does not invent one or claim it can check the full intent/swap/slot transaction.
Store/watchdog/lifecycle still enforce ValidateContinuationOperation and the
selection / claim / cancellation / reconciliation fences.

Fix-10 launch_plan emitter and lane.check/lane.state catalog rows are consumed
without adding any grants emitter or write authority. Grants does not emit
either row. Their producer/store controls remain in the integration catalog.

## Fix 10 review and channel worker jobs

ReviewVerifier now validates the service scope, bounded ended-run selectors,
typed diff/check/inventory candidate references, current lease/effect claim and
matching fixed test/export WorkerPlan. It still returns an owning typed
not_implemented before any verifier job or evidence result. It does not infer
a frozen post-run snapshot, complete coverage, checks, EOF or tool inventory
from candidate labels. The closed coverage schema is complete/partial/
unsupported/missing; the existing shared validators must receive actual
authenticated job output before lifecycle can accept a new live review.

ChannelWorker now calls the actual job/input/execution validators and reloads
the current WorkerLease, claimed outbox effect, protected channel runtime and
destination. Sealed channel_input and channel_payload objects must have exact
private service/operation provenance, bounded bytes, digest and actual EOF.
Send/read-back also compare the current committed worker binding. These are
read-only preflights, not worker preparation, claim, permission or delivery.
Prepare/Send/ReadBack all retain owning typed not_implemented results until the
real registration/identity/permit and authenticated worker result path exists.
There is no service-UID send or return of a fabricated uncertain/confirmed
provider result. The internal channel dispatch adapter belongs to messaging;
this lane does not edit its frozen dispatch name or invent an inside protocol.

Required handoff: the service/identity/helper owners expose the authenticated
fixed-worker endpoint/input/result mechanism, stage and worker identity recovery,
with current lease/effect/grants/endpoint checks. Review additionally needs the
protected frozen subject/required-check inventory and actual confined test/diff
jobs. Channel additionally needs authorized credential injection inside that
worker, real provider serialization/acknowledgement/read-back and interruption
reconciliation under the same provider key. The new schemas alone do not supply
these missing process/IO mechanisms. Owners: integration, service/store,
identity, admin/isolation, lifecycle or messaging, secrets, and this lane for
the jobs. None of these rows is closed by static compilation or fixtures.

## Launch materialization and LP-DATA-JOB-1

Internal Resolve now loads GrantResolveRequest's reservation and the actual
private service-origin launch_request bytes. It validates the operation,
request digest, target policy, root ticket or actual parent and creation edge,
current grants/expiry/delegation and issued-set replay. Its set/life IDs are
exactly the reserved IDs; member IDs are stable service derivations. The
public GrantsValidate preview remains separate. Retained-life resolution
reloads the previous LaunchBinding and complete plan/handoff; it refuses
missing recovery, changed life/run/home/history/workspace, stale policy and
revocation. Read-only resolution never claims an effect or commits a set.

MaterializeLaunch now consumes the real fix-11 MaterializationControl stage and
await ports. It validates the full stage, installed worker artifact, narrow
job grant shape, helper-held projection and store-retained DataStageID. Completion
requires ValidateLaunchDataResult, private original-operation result provenance,
exact acknowledged JCS LaunchData, actual manifest bytes/read-back hash and
fresh grants/source/storage checks. A planned record with DataStageID replays
that same measured stage. Historical records without it retain the prior
read-only verifier; they are not proof of a new job.

The old LP-DATA-JOB-1 missing-representation refusal is replaced. The actual
service/store/outbox and admin ports still return their owning not_implemented
errors in this checkout; those errors propagate unchanged. No service-side copy,
parent-claim theft, stage-ID guessing or pending-effect scan is introduced.

The confined RunMaterialization/RunInternalJob implementation consumes exact
WorkerBootstrap input, checks its own worker principal and helper root identities,
copies tree files into independent exclusive-created destinations, verifies
actual bytes and filesystem contents, prepares a private vendor home, and submits
bounded JCS LaunchData through WorkerResult. The actual acknowledgement is
validated. It does not infer process exit from that acknowledgement.

See dataworker/MATERIALIZATION.md for the fixed job payload and builder/consumer
sequence. MaterializationGrants uses already store-issued IDs, one read-only
/job/source data grant and no agent capabilities. EncodeMaterializationInput
prepares this worker's private opaque body without extending public Methods.
Output is an inert service-retained tree-manifest candidate; both the job and
outside stage completion must measure actual output before accepting it.

The current shared ValidateLaunchDataResult pins ReadBackSHA256 to the retained
Manifest.SHA256. That proves reference consistency, not a separately encoded
Controls-owner outside walk. The API/service owners must define and retain that
outside observation before this consumer can compare its entries with the
sealed output. The worker's implemented in-process walk and the synthetic
fixture process observations do not establish that external acceptance.

RunInternal validates the fixed binding/lease grammar and calls the real client
owner. Client.Open is still not_implemented. The shared client has no implemented
private worker bootstrap/native-principal bridge. Until service/identity/admin
implement that bridge and actual job namespace launch, RunInternal cannot
construct a MaterializationJob from an argv lease or a caller-authored identity.
The dependency bundle accepts opened roots, not caller paths or passed client
descriptors. The native entry opens only its helper-projected fixed job roots.

Tree copy/home preparation has an implementation. Reachable Git history still
returns an explicit admin-owned unsupported result: the protected Git export and
pinned Git runtime are not supplied by the current materialization handoff.
Ambient Git, a shared .git/object database or a guessed executable is not used.
Additional nonproject data views likewise require authorized projections; the
one-source stage cannot silently materialize them.

The Linux fixtures execute actual file copy/home preparation and acknowledgement
logic inside ordinary test-owned 0700 directories, with independent fixture
read-back. Native principal/claim/process/zero-exit DTOs remain explicitly
synthetic. They cannot certify actual UID/helper containment, terminal observation,
Git history, restart or installed serve acceptance. Those runtime rows remain
open. Current materialization claimant/expiry checks belong to the service;
completed launch-time stage claims stay historical and never authorize rerunning
the copy after their worker lease expires.

## Remaining read and portability limits

All scoped revalidation reads now keep fresh ReadViews open; policy reads carry
the actual life/level/role. Store.Grants and Store.Launch remain unscoped API
methods, so those two reads cannot select Scope.ReadView. The API/store owners
must define their snapshot-consistent equivalents or an authoritative combined
read. Final release still requires the store's current CAS/guard boundary.

Case-folding collisions, destination aliases and non-directory root entries
are rejected. Full NFC-equivalence checking remains open: the frozen module
dependencies do not provide Unicode normalization, and this lane does not add
an ad hoc partial normalization table or silently narrow all Unicode paths.
The tree copier uses exclusive creates and rejects EEXIST before acknowledgement;
its real raced-destination control remains a Linux runtime gate. Full Unicode
normalization still needs an integration-approved dependency/platform contract.

The designated-Mac/Darwin copy and native confinement cells are not authorized
runtime work on this Mac. Linux-only case execution cannot certify those cells.
Mutable-source swap, external-hardlink, nested-mount and requested Git-history
canaries remain the eight explicitly blocked OS mutation plans until their
real intake/job operations are available. Owner: this lane and the named
admin/platform/E2E dependencies. No unreached row counts as passing.
