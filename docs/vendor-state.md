Vendor homes mix renderer-owned configuration with opaque provider runtime files. The renderer's file list is defined once in internal/orghook/vendor-files.json and embedded in the Go renderer. Org inspection reads those named files directly and does not enumerate the rest of each instance vendor home. Runtime file contents, names, sizes, and symlink targets do not enter validation or its operation count. Owned settings and configuration retain the secret scan and regular-file checks.

The separate e2e repository supplies the org template exporter. Source org validation must pass before copying begins. The copy keeps owned vendor files and excludes runtime trees before copying or following them. Re-render the copied org before launching its instances so registrations bind to the destination. Mechanical exports and combined source views use the renderer's definition. The product publication scanner reads that definition directly and has no dependency on the e2e helper. Runtime files already tracked or staged in Git fail publication scanning with `vendor-runtime-not-publishable`; owned files continue through the existing publication rules.

The structured org command group has no native copy, export, or commit operation. Generated org initialization creates known protocol, definition, and state files rather than copying a vendor home. Raw third-party filesystem copies or Git commands outside the supplied exporter and publication hook do not apply these exclusions.
