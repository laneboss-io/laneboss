Laneboss

Laneboss is a launcher for supervised agent lanes: a supervisor session hands each piece of work to an executor in its own worktree, and the launcher records what happens to it, so that the supervisor learns it from events and not from the executor's own report.

Pre-release: nothing has been released and interfaces can still change.

Who it is for, and what you get

Laneboss is for supervisor sessions, and gives every session:

  • One command

    laneboss validates configurations, records events, renders briefs, checks the environment and starts, watches, resumes and collects lanes.

  • One versioned shared protocol

    Appended to every brief it renders, so that every lane is given the same rules, the refusal rule included.

  • One configuration per company

    Kept outside this repository and apart from every other configuration.

A supervisor session plans work and hands it to mini-supervisors, executors and reviewers. A lane is one such unit of work, with one brief, one executor and one worktree.

Laneboss is generic: it holds no company settings, credentials or state. A configuration names the secrets it needs and never holds one.

How it fits together

A refusal, in four steps

  1. A guard's pattern, written in the configuration, finds a refusal in the agent program's raw session records.
  2. Later shell calls that write the refused files or repeat the refused command are flagged as suspected workarounds.
  3. The supervisor gives a verdict on each file.
  4. With guards in the configuration, lane mark --state accepted or merged first scans every run to its end and is refused while a suspected workaround has a path without a verdict, a run is not covered or the scan's events could not be recorded.

--accept-uncovered records the decision together with what was not covered instead of refusing for a run that is not covered. A verdict of workaround does not block: the decision stays the supervisor's.

The judge on five test subjects

Works with Claudock: docs/claudock.md shows one runner that starts the agent program under the account of a Claudock profile, and cos, a small terminal front for accounts that take only headless requests; Laneboss does not need Claudock.

Install

Linux or macOS with a POSIX sh, and git and tmux on PATH; Python 3.11 or newer for the launcher, which needs nothing beyond the standard library.

With no checkout, one command installs the launcher:

curl -fsSL https://raw.githubusercontent.com/laneboss-io/laneboss/main/install.sh | sh

That line fetches install.sh from the repository's main branch; docs/install.md says what it does and needs, and that it runs what it fetches with your rights, which nothing checks. The second way is from a checkout:

git clone https://github.com/laneboss-io/laneboss.git laneboss
cd laneboss
sh scripts/install.sh
export PATH="$HOME/.local/bin:$PATH"
laneboss --version

scripts/install.sh installs into ~/.local without pip, network access or administrator rights. The quick start runs a whole lane against the invented configuration in examples/minimal/.
