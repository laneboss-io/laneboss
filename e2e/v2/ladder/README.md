# Mixed ladder inputs and handoff

The active converged-source gate order, installations/accounts and owner waits
are in ../cases/ladder/READY.md. Revision references below retain the restored
protocol's history; current implementation status is its source-anchored plan.

These are inert harness scenarios, not production authority. scenario.json
defines the ten instances and their authentic immediate parents. tree-a.json
and tree-b.json request separate stores, sockets, service/lane UIDs and workspace
roots. The administrator must refuse occupied IDs or paths, install real
draft.4 InstalledBinding and service-install files, and retain the allocation
receipt. A copied allocation JSON is never an installed binding or a login.

The source pins request claudock-cli 0.1.0 and codex-cli 0.146.0. These are
candidate ladder pins, not evidence of supported authentication or continuation.
The operator also pins the underlying Claude Code executable and its exact
version in the protected bundle. All three executables must be real installed
bytes; retaining only a wrapper, package launcher or mutable dependency tree is
insufficient. Adapter owners must confirm these pins before a live run.

Preparation records a random seed, the actual ordered runner draw and SHA-256
in draw.json and draw.sha256.json. The seed only shuffles two leaves of each
driver. Challenge paths, tokens and PING nonces use secrets.token_hex, backed
by the OS random source. Repeating the seed reproduces the draw while every
challenge path/token/nonce changes. observer-plan.json stays outside all agent
grants. A parent receives only its own data, its delegated child task sources
and its direct children's PING nonces. No sibling private data is delegated.

task.md and parent.md/leaf.md render one exact brief per instance at run time.
The installer resolves approved full model names, profile grant handles, real
wall/spend/CPU/memory/process/disk budgets and subset data grants into the
installed dispatch.json for each instance. It retains both original preparation
and final delivered bytes. It must not invent a bearer credential or substitute
the fixture runner. Parents alone start and collect children; the harness starts
only L6 in each configuration. Root idle turns use lane loop and an actual
enrolled scheduler, preserving explicit vendor session/history identity.

## Installed administrator and serve handoff

The administrator namespace and boot scripts are present at 693011a. The
namespace script prepares OS prerequisites; it does not consume ladder-install
JSON or emit a two-tree context/result response. The legacy source-box recipe
remains stopped at its unimplemented handoff, rather than passing that proposed
stdin protocol to the real prerequisite installer.

The installed phase consumes serve2 179f3f0's real report.json, config-relative
manifest.json, exact initial bundle, publication receipt/read-back and stage
timing journals. Serve emits no frozen E2E context, and its cleanup stops both
owned units. A verified report is retained evidence, not a running ladder.
The installed wrapper never rebuilds, installs or restarts that service.

The supervising installer must separately supply tree-a and tree-b, their real
active bindings, approved vendor/runtime/model/profile enrollment and fresh L6
tickets. Supply the ordinary frozen candidate E2E context and exact ladder.json,
with result next to test_root and a distinct evidence_root. These are actual
caller-supplied files, not claimed outputs of serve2. A readable protected copy
of serve evidence is required by the non-root controller. StartRequest, Ticket
and ProofRef files stay outside prompts. Consumed serve proofs and closed read
sessions cannot become the live authority.

The current installed-only phase plan is in cases/ladder/READY.md (relative to
e2e/v2), with a validated per-row dependency and landed-status inventory.

The fixture schema is laneboss.ladder-live.v2 with contract_revision equal to
v2.0-draft.4. Its other fields are plan_directory,
observer_binding, trees and artifacts. artifacts maps binary, helper,
claudock-cli, claude and codex to canonical immutable executable paths. trees
contains config, binding_file, start_file, ticket_file, request_id,
idempotency_key and binding. Each binding is a harness inventory with store_id,
socket, service_uid, workspace_ids and lane_uids. Service-issued workspace/store
IDs and actual identity.bound UIDs must agree with the public CLI records.
No caller-supplied inventory grants authority. The optional read_sessions map
must name tree-a and tree-b, each with binary and proof_file. Its binary equals
the additional artifacts.reader, a protected build of e2e/v2/readsession.

The prep receipt schema is laneboss.ladder-prep.v2. It has artifact_sha256,
configs, allocations, controls, sysctls_before and sysctls_after. The allocations
are the two exact requests. The sysctl maps contain unprivileged_userns_clone
and apparmor_restrict_unprivileged_userns, both 1 and unchanged. controls names
unprofiled, profiled and unprofiled-copy. Each is a standard path/sha256/bytes
reference to its real command receipt, retaining exit_code, timed_out,
stdout_sha256 and stderr_sha256. Raw outputs also remain in the installation
evidence. Missing or failed controls stop before any model launch.

## Independent observation socket

The observer is separately installed and reviewed by the supervising operator.
No implementation is claimed here for the missing authentic parent timing
transport. Its absence is not_implemented, owner lb-v2-integrate. The E2E client
in ladder_observer.py requires a root-owned protected Unix socket, verifies
SO_PEERCRED and binds every fresh nonce to candidate and draw hashes. Its
protected binding has schema=laneboss.ladder-observer.v2, socket, uid=0 and
artifact_sha256. No caller-authored observation file can become a case
success. Agent-authored timing, a human reader's clock and internal DB reads
are excluded from acceptance.

Frames use a four-byte big-endian length and at most 1 MiB of UTF-8 JSON. A
request has schema=laneboss.ladder-observe.v2, nonce, artifact_sha256,
draw_sha256, method and params. A response repeats the first four fields and
has exactly one result or typed error. Only preflight, sample, finalize,
collect exist. Lifecycle params name the two configurations; these actions
cannot execute arbitrary commands, supply authority or select an agent UID.

preflight requires ready=true and coverage for durable-waits, privacy, kernel,
overlap, source, actor, collection, read-auth, root-turn, barrier, archives and
configuration-events. Claims of
coverage must be backed by the sealed observer's real implementation. Missing
coverage refuses before either root start. There is no fixture observer server.

sample supplies clock_id, observed_ns and live_refs. Each ref names config,
life_id, before, after, before_ns and after_ns. before/after are identical
kernel process identities with pid, generation-bound start and all four UIDs.
All twenty distinct agent identities must bracket the same observed_ns. This
proves a common live instant; two successive ten-agent snapshots cannot pass.
The observer counts actual vendor agents, excluding shell helpers/stand-ins.
Each ref also has executable_before_sha256 and executable_after_sha256 from
the kernel process image at both observations. They must match the retained
Claude Code or Codex bytes assigned to that life. A wrapper or unrelated live
process cannot count as a vendor agent merely by sharing its lane UID.
Its enrolled bounded barrier and the parents keep first turns overlapping.

finalize returns runs keyed by configuration, each with waits, privacy,
manual_requests, kernel_final, sources_before, sources_after, unresolved and
archive_readbacks, mutations, reads, launch_audits, review_requirements, presence
and authority_events.
It cannot replace CLI events, lanes, blobs, answers, bindings or artifacts.
waits bind event ID/sequence, life/run, authenticated reader life, visible,
clock_id and commit_ns/received_ns in one measured monotonic domain. Nanoseconds
are relative to a retained observer origin, within exact JSON integer limits.
Every successful child run requires its actual parent receipt within two seconds.
Recovered wall timestamps cannot manufacture these observations.

Privacy probes cover both directions of every actual sibling pair, retaining
reader_life_id, target_life_id, probe_id, containment_id, a successful own_read,
and false sibling_read / private_mail_read / private_session_read. The observer
performs registered harmless canaries and independent public ACL reads at the
real lane authority. Lack of a permission error is not a denied read.
manual_requests binds the actual requester, first_mail_sender and event_id;
the verifier cross-checks both against the public queued mail and lane.turn.
kernel_final covers every life with known=true, actual host_uid,
containment_id, observed_ns and a genuinely empty processes list, including
detached children and live threads. Unreadable/unknown containment cannot pass.
The source maps retain the same nonempty path/hash inventory before and after.
authority_events contains original configuration-level service events without
a life/run selector, including human sessions/proofs and ticket issuance.
The public collector selects exact life/run pages with independent cursors;
the observer cannot replace those public run events. Refreshed authority
snapshots must preserve prior exact events and durable sequences. Missing this
authentic protected source fails preflight before root dispatch.
archive_readbacks binds each child's life_id and archive_receipt_id to a
service-issued content BlobRef and independently measured read_back_sha256.
The case reads and retains those archive bytes through blob read, then compares
their actual digest with both the parent receipt and outside read-back. An
opaque nonempty manifest or two equal claimed hashes cannot satisfy this gate.

collect is idempotent, stops only registered resources by lifetime-bound PID,
retains real cleanup/archive receipts and returns processes_quiescent,
temporary_resources_collected and receipt. It collects installed services and
the retained roots after parents have collected all nine children per tree.
The same action must handle partial administrator setup and failed runs.

## Draft.4 observation details

The tree entry now uses ticket_file instead of the earlier generic root proof
file. It contains the actual issued Ticket with principal_id, config and
endpoint_generation. The verifier compares it with identity self and the
service's ticket.issued/redeemed events. Root start carries root_ticket_id on
its human endpoint. A root-operation ProofRef does not replace that ticket.
Fresh human.session proof files stay outside prompts and evidence credentials.

The observer has no proof-provider action. The E2E readsession process uses
production client.Open and one verified connection/session for event pages,
blob chunks and projections. All requests remain public RPCs; it has no store
or helper access. Native client errors retain their owner and there is no
fallback. An absent reader keeps the prior pre-start refusal, using zero proofs.
A configured reader uses one genuine proof per session window, regardless of
poll/chunk count, with actual process/proof/exit receipts. Active reads refresh
the same session generation/idle expiry; absolute expiry remains fixed. A
renewal reads a new confirmed proof from the protected file and rejects reuse.
A 6900-second run requires at least four active windows per tree. These counts
describe the implementation and planning bound, not an executed live run here.

preflight additionally requires draft4-mutations, draft4-reads and
draft4-releases. The normalization below is proposed E2E observation data,
not serialization of internal production types. Integration/service and the
independent observer owner must approve and implement its authentic source.
No management file is opened by the acceptance case and no caller-authored
JSON file can stand in for an observed public request, reply or connection.

Each mutations entry contains request, actor, response, receipt, transaction,
event_ids and replayed. request/response retain the actual frozen RPC envelopes.
actor is independently resolved, not a client body label. receipt normalizes
retained config, key (method/idempotency_key/request_sha256), actor, operation_id,
reply, first_seq and last_seq. Its config comes from the original retained
receipt, never from the current query scope. reply contains the exact typed
result. Replays preserve that entire receipt and cannot create another life.

transaction normalizes nonempty StateWrites field names, submitted event kinds,
effect payload names and guard kinds as fields/events/effects/guards arrays,
plus reply indicating the actual typed reply was present. draft4-writes.json
pins the applicable public rows. It permits WorkerLeases on start/adopt/resume/
turn and cancellation fields/events while rejecting unlisted writes or missing
replies. The case never submits these internal shapes as a product RPC.

Each reads entry contains request, actor, response, transaction, connection_id
and session. Non-public human session has connection_id, proof_id and event_id;
the real session event and read must belong to the same observed socket/principal.
A read frame carries no ambient operation proof, and its transaction changes
no state/events/effects/guards. Lane/public reads have an empty session object.
The case cross-checks every collected CLI intent and rejects proof reuse on a
different connection. Final tails drain session events created by the final
blob/list calls before the observer refreshes its measurement projection.

helper.released carries the exact draft.4 ReleaseReceipt. Bind its allocation,
life, UID, containment and causal operation/effect. Require the helper's own
known zero process/connection/job/writable-export measurements, not a caller
survivor field. Every cleaned child's allocated leases need measured releases;
the external collector also verifies the retained roots' release receipts.
A validated quota continuation keeps the exact typed ProfileSwap fence.

## Fixes 10 and 11 normalization

Initial launch mutation observations now identify transaction.kind as
launch_reservation. That private reservation commit retains LaunchPlans and
PlanLaunch, not a fabricated ready Lane write. Root guards are exactly Ticket;
lane starts carry no borrowed human guard. Retained turns carry Cancellation
and, for humans, their exact Proof. Public write_shape remains the closed public
catalog and gains PlanLaunch; reservation observations are not public Params.

Mutation receipts additionally retain policy_generation and simulated_presence.
policy_context names current_generation and use=fresh, exact_replay or
retained_selection. Fresh work uses current policy; a replay or existing
guidance claim retains its approved historical generation and bytes.

Each launch_audits entry has reservation, record, prepared, identity, recovery,
authority_event_id and policy_at_release. The first five carry the actual
retained contract objects; IdentityCommit uses normalized snake_case keys.
policy_at_release is the observed approved generation immediately before the
gate opens, not the later generation when evidence is reviewed. All referenced
original request/spec bytes must be retained through public blob.read. The
verifier checks role/level/driver, target, plan/spec/home/capture, exact digests,
committed identity and consumed ticket/proof or authentic starter. This remains
proposed protected observation normalization; no producer or public method is
invented by serializing those internal types. Preflight must demonstrate
draft4-launch-pins, draft4-policy, draft4-presence and draft4-review.

Each human read session observation also retains generation, expires_at,
idle_expires_at and simulated_presence. Revisions advance, idle expiry never
exceeds or replaces absolute expiry, and the original session/proof/connection
binding remains fixed. review_requirements maps actual child life IDs to the
current protected required check names. ReviewEvidence must match the ended
launch/run, snapshot, session and pinned inventory, with successful worker
checks, complete tools and authentic capture EOFs. It is not a requester list.

Presence is retained in hash-checked presence-summary.json evidence and the
outer harness summary, preserving the frozen case result envelope. Software
marks propagate to every dependent row and aggregate as presence=simulated,
human_approval=not_proven. Unmarked rows are not_measured here. No software
authenticator, faults build or missing mark proves physical human approval.
