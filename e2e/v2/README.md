# v2 installed acceptance harness

The active two-tree handoff is [cases/ladder/READY.md](cases/ladder/READY.md).
The f64e2ea harness slice is restored as content on the converged tree.
Its source port inventory is [cases/ladder/plan.json](cases/ladder/plan.json);
landed means a source implementation, never installed or live acceptance.

Use the installed wrapper's service phase to verify item-1's retained report,
publication and collected units. Supply two separately installed active trees
and fresh authority for launch. Serve's stand-in runner and simulated presence
cannot be promoted to a real vendor or hardware approval.

All runtime, build, unit and native checks run on the authorized disposable
Linux machine. On the authoring Mac, only the requested static checks run.
Harness units use scripts/v2-e2e/unit.sh; the Go test proxy in this directory
runs the same strict units and turns skips/expected failures into failures.
The readsession Go package also checks real-store event reads. Root-tagged
observer canaries exercise actual Unix credentials and response correlation;
their echo server supplies no ladder acceptance facts.

run.sh discovers each frozen case.json and invokes --context FILE --result FILE.
It checks source/binary pins, every declared reached assertion, actual command
exit, evidence hashes, independent observations and collection. An unreached
setup failure cannot kill a product mutation. The ladder verifier rejects
wrong answers/paths/ancestry, early PONG, false actor/end records, incomplete
capture, historical reviews, bad release/archive facts, survivors and sequential
trees through the same code used for candidates.

The ladder starts only two L6 roots. Authentic parents start and collect the
remaining eighteen lives. It reads public events with one exact life/run and
an exclusive cursor per selection. Configuration-level authority events require
the separately protected observer source. Missing observer coverage stops
before live dispatch. Shared read-session processes consume one fresh genuine
proof per session window, preserving absolute expiry and simulated provenance.

Source readiness, real accounts/installations, native observation, supporting
acceptance and owner-in-person ceremonies remain separate gates. Launch checks
sealed SERVE-STATE, MIGRATE-ROLLBACK and INTEGRATED-RELEASE evidence on the exact
artifact; a narrow records case or plan-only migration cannot replace them.

The older source-box recipes are preserved for review, with their original
typed stops. Their go1.26.5 pin conflicts with the current source installer's
go1.26.0 pin, and their proposed administrator tree-install handshake has no
producer. The installed wrapper does not run that recipe, rewrite installation
policy, provision a machine, authenticate a profile, purchase capacity, or send
an owner message. Follow READY.md for the current supported handoff and the
precise remaining work.

The historical CONTRACT-GAPS.md, contract-requests.md, FIXES.md and REVIEW-FIXES.md
retain provenance for the restored slice. Current implementation status comes
from READY.md and its source-anchored plan, not those historical claims.
Independent Claude and Gemini reviews, complete installed controls, retained
evidence and external collection remain release gates.
