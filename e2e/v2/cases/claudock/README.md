# Claudock live acceptance

This case is written before the adapter. It is a live gate, not a vendor
stand-in. Run it only on the supervisor's authorized Ubuntu 24.04 box, through
the installed production CLI and service. It must fail while composition,
credentials or isolation are missing. A fixture/unit-test result cannot satisfy
this case. Each credential mode needs its own run and retained evidence;
headless success does not enable helper or API mode.

The separate `mutations.py` command is credential-free unit verification. It
requires a green default/faults × umask 022/077 preflight before 80 Go red
controls, plus 24 Python case-consumer controls between green 20-test consumer
suites, then repeats the candidate matrices. Test setup failures never count
as killed production mutations. Run it on the authorized Linux box, not on the
authoring Mac; it does not satisfy this live acceptance gate.

The unit controls include retained credential-container identity, full terminal
observation shape in both slot release and quota classification, and exclusive
generated-file seeding. Each mutation must
compile and reach its named behavioral assertion. Canonical kernel observation,
mount isolation and live vendor compatibility remain independent prerequisites;
these controls do not supply those receipts. The adapter's
[contract note](../../../../internal/v2/runner/claudock/CONTRACTS.md) tracks them.

The harness passes exactly `--context FILE --result FILE`, using the frozen
v2 case/context/result formats. Supply a delegated installed configuration and
two same-provider profile grants. No credential value belongs in a case input,
source tree, fixture home, command argument or result. The configuration must
already authorize the live requests and budget. This case never logs in or
chooses a paid fallback.

For draft.4, execute this case and its CLI descendants in an authentic parent
lane's UID/containment with its installed read-only lane binding. The parent's
actual spawn/control/grant authority must cover every prepared test life.
`context.binding_file` names that exact draft.4 projection and is passed on every
CLI call. A host process holding a copied binding, a human UID or a ticket label
cannot supply this identity. The case selects no human root-ticket path.

Every request retains random 128-bit request/idempotency IDs and exact argv
before execution. Uncertain mutations are not retried with fresh keys. The CLI
prints typed result bodies, so Health's `protocol` field is retained directly.
Follow output contains an initial EventPage plus correlated StreamFrames; the
case retains both and requires a real end for the selected life/run. It also
reads back intervening committed history so an already advanced quota run does
not hide its earlier capture/swap events.

Vendor verification reads the actual scoped `config read` show projection,
then verifies its config/generation and installed Resource IDs/hashes/versions
with `verified_loaded`. It does not call the human-only dashboard from a lane.
The policy/packaging owners must expose those scoped verified resource receipts;
absence is a failed dependency, never permission to substitute fixture claims.
Worker input/plan uploads use the frozen `artifact` class.

## Required operations and independent observations

1. Retain the exact installed Claudock and Claude executable bytes, digests,
   versions, help, registry/auth documentation and structured record examples.
   Claudock must actually consume its one-profile projection and the selected
   run credential inside the production outer sandbox. The service's mode
   verifier must reject an absent live compatibility receipt.
2. Start through `lane start --config NAME --request FILE`. The task contains
   an unpredictable nonce. Require a real structured init/session event and
   successful work, then resume with a question about the first nonce, without
   putting that nonce in the follow-up. Turn again with a second question.
   Check primary capture and committed start/end/session events, not merely
   the start response or a model's claim that it remembers.
   Immediately after run 1, a confined grants test-child probe must find the
   unique actual vendor transcript and report a regular single-link file with
   mode 0600. The helper must establish umask 077 before vendor exec and the
   service VerifySlot must validate its actual bootstrap proof. The probe does
   not repair permissions or copy transcript content.
   A further turn makes the real vendor use Write/Edit/Bash to create an
   unpredictable file in /work/main. Require the producer-bound vendor tool
   record, then read/hash the exact bytes independently through the installed
   CLI's grants test-child path. Claimed completion cannot satisfy this cell.
3. Use already delegated same-provider profiles A and B. A real externally
   observed provider limit plus fresh outside usage/room evidence must drive
   exactly one quiescent slot change to B. Retain the original history ID,
   session ID, logical cwd, model, logical turn and remaining budget. Do not
   burn requests to manufacture exhaustion. An exhausted authorized profile
   or an independently retained live quota event is a prerequisite.
4. Plant independent random canaries in the sibling's history/token paths.
   Prove the observer can read them and an own-lane control works. Through the
   same installed launcher, execute the syscall probe under the tested lane's
   UID/grants with vendor hooks absent and inner sandbox disabled. Retain the
   actual open/read errno and independent observer read-back. A model saying
   "permission denied" is not this observation.
   Both existing sibling paths must return EPERM or EACCES with zero bytes.
   ENOENT is a failed/missing canary, even if the independent observer can read
   some other path. This case has no absent-path cell.
5. Preserve a real structured quota/usage event and exact byte hashes. Quote
   the same text in user, assistant and tool content, and exercise a real
   auth/guard refusal. None may cause a slot change. Plain diagnostic text,
   an exit code alone and lane-authored transcript files are not triggers.
6. The wrong executable digest, a link to a shared vendor home, absent
   conversation history and changed cwd/session must fail before execution.
   Inspect committed events and process observation independently: no agent
   executes on these controls. Recover only by restoring the original
   authorized artifact/home, never by adding an override flag.
7. Stop owned runs through the CLI and require exited processes with zero
   survivors before collecting runtime slots. Keep the private history and
   primary evidence, excluding transient credentials from archives.

Draft.4 collection distinguishes a nonexecuting abort from process release.
An aborted prepared gate requires a committed service-origin no-execution
launch.failed event and matching outside zero-survivor observation. It does
not require a fabricated exited ReleaseReceipt. A real release uses its own
quiescence.handle.target and retains independently measured zero processes,
connections, queued jobs and writable exports, even when the lease-level event
omits Run. Unknown/null/nonzero counts and the old HelperLease payload fail.
Stop cancels pending continuation for executed runs. Lifecycle/helper completion
must retain the actual abort/release receipts; caller-authored zero survivors
cannot replace them.

After a quota end, the case waits for the current run to advance before opening
another follow stream. Cursor pages clear since. A candidate reaches the full
assertion only after all stages and collection; red reachability names its actual
cell. Synchronous invalid-launch refusals require an unchanged prior run and
no execution. Only accepted asynchronous launches require launch.failed plus
prepared-or-exited zero survivors for the actual current failed run.

Result quota fixtures follow the documented pinned result/errors fields,
including an absent or success subtype when is_error is true. Quotes,
successful terminal results and auth/guard errors remain negative controls.
Live primary captures additionally require fix 9 BindingID and use stdout or
the optional `vendor` stream. Fresh snapshots may change across runs; workspace
ID/project/base/branch/logical cwd and the private session must stay fixed.

Fix 11 freezes the exact outside usage envelope and pinned five-column TSV.
The adapter now consumes that source, authenticates the usage worker, checks
fresh post-exit from-profile exhaustion and retains the private usage_window
reference in every limit signal. The f11-usage controls name the percent,
freshness, profile, producer and raw-source assertions. Unit fixtures supply
synthetic protected records and real-shaped TSV, not live authentication.
The raw lane-local forged-envelope canary still needs the installed outside
producer and a retained primary range from the harmless same-lane writer.
LimitGuard also requires whole-run coverage. Auth failure, cooldown and
Room.Available=false cannot substitute for exhaustion. The quoted-content cell
is not this raw-pipe canary; no live-forgery pass is claimed.

The ProfileSwap and resumed LaunchEvent must retain the same exact swap,
delegated grant, eligibility and generation/epoch fence. History, task and task
failure/retry counters remain fixed, with a truthful next run and no budget reset.

## Red controls

Run each control on its distinct artifact before the candidate. A setup
failure is not a killed mutation. The named assertion must have reached the
operation that demonstrates the defect.

| Mutation | Observation that fails CLAUDOCK-TWO-TURN |
| --- | --- |
| `shared-home` | A sibling canary is read through a shared-home link. |
| `digest-bypass` | A modified vendor executable runs despite its pinned hash. |
| `new-conversation` | Resume starts a replacement conversation or loses the nonce. |
| `quoted-limit` | Quoted limit text causes a credential swap. |
| `auth-as-limit` | An authentication/guard refusal causes a swap. |
| `history-moved` | Slot rotation changes private history, cwd or session. |
| `mode-without-proof` | A fixture receipt enables a live credential mode. |

The entry retains CLI requests, stdout, stderr and process exits. It reports a
failed assertion, not a skip or a passing empty result, if a required dependency
or independent canary/quota observation is unavailable. The current scaffold
is expected to fail at service health/start. The adapter's README describes
the integration callbacks that must be supplied before the live gate can run.

Fix 10 adds 15 unit red controls for reservation child pins/retention, current
capture-refusal policy and approval metadata, snapshot/replay, refused
continuation, current policy port errors and prepared agent identity. Their
positive/negative consumer fixtures are synthetic and cannot establish real D6
authority. The service/publisher/helper must validate the consumed approval and
current generation/revocation before any incomplete isolated start. This live
case continues to require registered primary capture and full evidence; an
allowed refused disposition cannot satisfy CLAUDOCK-TWO-TURN.

## Installed-case inputs

The shared harness prepares these files beneath `context.test_root`, through
the actual installed service/grant/credential setup. They are names, retained
sources and frozen request objects, never credential values or claimed passes.
The entry does not edit private state to manufacture an invalid home or quota.

- `start.json` is the frozen `api.StartRequest`, with a valid delegated project,
  role, grants, policy generation and authorized budget. The entry replaces its
  task with an exact uploaded unpredictable prompt. An already exhausted
  authorized profile A and same-provider profile B with room are needed; the
  case will not spend requests to force exhaustion.
- `vendor-inputs.json` maps `claudock` and `claude` to `executable` (the frozen
  `api.Executable`) and `bytes_relative`, `help_relative`, `version_relative`,
  `auth_relative`, `records_relative`. Those paths identify actual retained
  vendor artifacts/help/source/records beneath test_root. Public resource
  projections must report the same ID/version/hash as verified loaded.
- `probe-request.json` is an `api.TestChildRequest` with a committed candidate
  object containing this case's exact `probe.py`. `probe-plan.json` is the
  installed grants worker's `api.WorkerPlan` for that probe. The entry replaces
  its `input` BlobRef, uploads the exact plan, and invokes `grants test-child`.
  This same read-only syscall probe also supports the `workspace-write` path
  and a bounded `transcript` lookup with the actual session UUID. The worker
  must project the target child's real home/workspace for those jobs. Setup
  bytes are retained once and must remain identical on every repeated use.
  Do not guess an unfrozen test-plan schema or execute the probe as the service
  UID. A missing worker adapter is a failed dependency.
- `probe-paths.json` maps exactly `own`, `sibling-history`, `sibling-token` to
  `logical` (the probe's path) and `observer_relative` (the independent canary
  file beneath test_root). Plant unpredictable harmless canaries, include a
  world-readable denied canary, and make only the own path granted. Both denied
  paths must actually exist in the tested namespace. No real
  credential is copied into a fixture. The observer reads/hashes the actual
  bytes before and after the confined syscall probe.
- `negative-controls.json` maps `wrong-digest`, `shared-home`,
  `lost-conversation`, `auth-refusal`, `quoted-limit` to `request` (a valid
  `api.ResumeRequest`) and `since` (the saved sequence). The first three also
  carry `expected_code`. The harness prepares their ended lives and actual
  invalid artifact/home/history conditions in this configuration's disposable
  scope. Both an immediate typed error and an asynchronously failed operation
  are supported. `not_implemented` or a setup failure cannot satisfy those
  controls. A synchronous refusal leaves the old run unchanged, with no launch
  events or execution. An accepted asynchronous request requires `launch.failed`
  with no execution and an independent zero-survivor observation for its actual
  failed run; an aborted unopened gate may remain prepared. The auth cell uses a separately authorized real
  vendor refusal and must not rotate. The quoted cell is sent a fresh quoted
  diagnostic by the entry and must actually emit it without a profile change.

Use a fresh evidence directory and result path for every phase/mode/artifact.
The entry maps red mutation IDs to the specific reached public operation;
missing setup for another cell is not a killed mutation. `mode-without-proof`
