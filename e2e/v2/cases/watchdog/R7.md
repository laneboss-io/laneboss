# Watchdog R7 protected boot staging

Starting revision: `445c033c`. The watchdog runtime descriptor and canary asset
now reach the installer from protected source staging. The existing protection
check is unchanged. The supervisor reruns the installed watchdog item; this
continuation claims a staging regression pass, not installed acceptance.

The reported installed failure was reproduced with the real public
`case_watchdog.boot()` entry. Its `wd_item.boot()` implementation returned both
asset paths from `case.keep()`, beneath the evidence directory. A private leaf
directory does not satisfy the installer's protection check when an ancestor
is writable. The source stage and evidence directory have separate roles.

`wd_item.boot()` now creates a private `wd-boot-inputs` directory under
`case.stage` and calls `provision.immutable_input()` for both `wd-run` and
`wd-target`. That helper checks every ancestor, writes exact bytes exclusively,
syncs them, makes the files read-only and verifies them through the protected
reader. The returned asset paths name those staged files. Exact evidence copies
are still retained. The independent canary observer keeps its original private
evidence file, whose permissions differ from the read-only runtime input.
No protection check, installer fallback or owner policy was changed.

The existing G0 profile-binder test also calls the actual boot entry. It now
uses a protected temporary source stage on the disposable root Linux step,
copying the real role templates there. It no longer treats a user checkout as
root staging. Its profile-selection assertions remain unchanged.
