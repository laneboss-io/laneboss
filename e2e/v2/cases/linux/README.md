# Linux OS acceptance

The installed producer is `scripts/v2-serve/case_linux.py`, using the published
G0 v1 contract. `boot(case)` returns measured bundle documents/runtime assets
before installation. `prepare(case, require, fail, blocked)` supplies the
populate, transport and independent collection callbacks. `abort` retains
unfinished collection and stops product mutations after a native refusal.
The original installed human is reused under the `itemlinux` catalog prefix.
No second configuration or signer is created by this path.

The shared exporter allocates the frozen input/output scopes, retains the
producer's exact leaf bytes and invokes the unchanged manifest entry. The
entry forwards product RPCs over G0's private observer channel; the outside
coordinator uses the original human and real installed CLI. Native hooks keep
actual lease/workspace/canary observations outside the tested lane. The same
verified collector receipt is reused after entry exit.

The standalone `run.sh --context CONTEXT --result RESULT --plan PLAN` remains
available outside G0. Its direct producer helper is `prepare_inputs`.
[HANDOFF.md](HANDOFF.md) defines inputs and remaining installed cells/reds.

The plan names the cell, an actual start template, a private supervisor
authorization file, and a private native fixture. Authorization explicitly
binds configuration, cell, driver, full model, effort, selected profile grant,
budget, enrolled runtime digest and expiry. The schema is
`laneboss.linux-live.v1`. Its `allow_model_request` must be true. No example
authorization file is shipped. An empty grant list or missing authorization
stops preparation before task upload, ticket creation or lane start, and
retains `linux-wait.json`. The ordinary case entry exits 69 with OS-LINUX
unreached when real profile grants are absent. It does not claim collection.

`boot(case)` stages the actual canary only as the selected `linux-canary`
runtime asset with read-only mode. Its retained evidence copy and digest do
not add a separate publication object. Plan-file bundle documents must be
reachable from the installer's selected manifests, runtime, sources, projects
or data trees; an orphan document still refuses installation. The matched
installed runtime must contain the canary bytes; a late manifest edit is
invalid. The native fixture describes installed logical paths and protected targets. It rejects
preselected UID/cgroup fields and old helper leases. The observer inventories
the installed UID pool before start, then reads the new start's actual launch
event, helper journal and workspace registry. It joins that operation's life
and containment to the real `lane check` handle and checks the workspace inode.
It retains the original administrator bytes.

The cell also supplies `lane_gid` from that same actual lease. The outside root
observer drops to the leased UID/GID with empty supplementary groups and
actually opens outside, readonly and nested canaries for read and write before
releasing the canary input. The pinned canary waits for that exact input hash.
A denied open is a fixture failure: DAC would hide the boundary under
test. The probe does not truncate or modify a canary. Its actual byte digest
and errno are retained. Each foreign TCP/UDP listener receives random control
bytes before start; later counts are deltas from that measured baseline.

The focused root Linux package command is:

```sh
go test -count=1 -tags laneboss_root_canary \
  ./e2e/v2/cases/linux
```

It runs 28 producer controls, six existing consumer controls, 18 G0 hook/adapter
controls and cross-vet for linux/amd64 and darwin/arm64. `TestLinuxBootBundle`
also runs actual `boot()` output through the shared fixture exporter, real
bundle assembler and `admin.RunInitialValidation`, including `initialClosure`.
It covers no plan, an empty plan, selected plan documents and the orphan
control made by removing their project selection. Plan assets use their real
byte pins. Exact fixture inputs are retained in the test log as compressed
JSON with hashes. The authority double is confined to component
tests. Real DAC, listener and detached-process controls run on the authorized
Linux box. These results cannot establish an installed OS-LINUX verdict.

The shared exporter is now imported from its published implementation.
The remaining live work needs an explicitly authorized real profile/runtime,
actual installed fixture publication,
the helper descriptor control and independent review inputs. The signal,
foreign IPC and permitted listener fixtures are actual owned OS resources;
their unit controls do not establish installed routing or confinement. The
producer does not claim these prerequisites from a JSON label. The installed
supervisor must retain the exact first missing/refused gate and actual
collection; a unit result cannot close it.

For the fresh Ubuntu 24.04 test host, use `sh BOX-SUITE.sh`. It supports
amd64/arm64, checks Go and sudo, installs the small unit dependency set,
prints each step and actual exit, and stops dependent work on failure.
It ends with the suite's real exit code. The installed serve rerun remains
separate. `prove_wiring.py` first runs two deciding assertions against the
exact retained R1 `base.py`, then runs the current wiring candidate. The base
must fail because boot is absent and prepare has its old signature. These
units and the declared vendor stand-in establish no installed OS-LINUX pass.

`matrix-required.json` enumerates the conservative complete cross-product of
two real drivers, two unchanged restriction settings, both hook modes, and
current/ABI-3 kernels. Every one of its 16 rows initially says incomplete.
A measured current-kernel cell does not credit an ABI-3 cell. Separate host
authorization and real profiles are required; this lane changes no sysctl.

Run this case only on the supervisor's disposable Ubuntu test machine. It
uses the installed CLI with one explicit configuration. It never starts a
service, authenticates a vendor, installs a profile, changes a host switch or
provisions a machine. The harness supplies those prerequisites. A missing
dependency is a reached failure only if its public operation was attempted;
it cannot kill a boundary mutation that never reached its canary.

The matched installation and binding use contract revision `v2.0-draft.4` and
backend `linux-bwrap-landlock`. Every CLI call passes the context's explicit
`--binding-file` as well as `--config`, retains fresh request/idempotency IDs
and uses the shared CLI/client request preparation. The case does not construct
another RPC digest implementation. CLI stdout must be the actual typed result
object. Evidence directories are created mode 0700 under the observer identity;
existing shared/foreign evidence directories refuse. Keep world-readable
outside canaries and their searchable fixture ancestors separate from private
evidence, so ordinary DAC cannot hide a deliberately removed boundary.

The harness invokes `sh run.sh --context CONTEXT --result RESULT`. The frozen
context lives outside the checkout. Alongside the context's `test_root`, the
harness supplies `linux-input.json`, with schema `laneboss.linux-case.v2` and
the administrator-observed dedicated `service_uid`:

* `cells` is a nonempty array. Each cell has `id`, `restriction` (0 or 1),
  `abi` (at least 3), `hook` (`absent` or `allow`), `inner_sandbox` (`off`),
  `start_request` (relative filename of an exact `api.StartRequest`),
  `stop_reason` (a `BlobRef`), `observation` (relative filename of the
  untrusted canary's JSON output), `outside` (relative observer canary path),
  `outside_sha256`, `worktree` (relative path observed before/after clean),
  and `marker` (an independently random argument carried by the canary and
  its double-fork child). `cgroup_relative` is the actual administrator-leased
  run cgroup beneath `/sys/fs/cgroup`; it is an observer input, never a path
  accepted as launch authority. `protected` maps `readonly`, `nested`, `state`
  and `sibling` to `{path, sha256}` entries for the actual delivered/denied
  files. A hash of only the grant's source cannot replace delivered-file
  observation.
  `lane_uid` is the actual exclusively reserved run UID from that same
  administrator lease, never a prediction or a value supplied by the lane.
  It must have no live process before start and differ from root, service and
  observer. The observer needs authority to signal that owned UID's exact PIDs
  through pidfds; it never invokes sudo or kills command-line patterns.
  `canary_input` names the exact relative JSON input file passed to canary.py.
  Its raw hash is checked against the canary output. The four foreign TCP/UDP
  addresses must be local test-box addresses with fixed nonzero unused ports;
  the case binds its own outside listeners there. The harness must leave those
  ports free. IPC and permitted-network controls retain their separate fixtures.
  `review` supplies the exact `diff`, `checks`, `record_inventory` and
  `refusal_resolution` inputs for the real `lane review` operation during
  collection. Those are committed evidence references, not fabricated receipts.
* Each start request's retained task runs `canary.py` and its real syscall
  inputs from the main grant, then waits for stop. The selected driver is
  either `codex` or `claudock-cli`. The task is executed by that real driver;
  neither a stand-in driver nor success text proves this cell. The canary's
  output is read as data by the outside observer after the actual CLI start.
* `red_controls` names the mutation for the red artifact. The candidate
  runs all declared cells. A red artifact must reach the same canary and
  expose the changed behavior, rather than failing setup.

Required cells cover both restriction values, both hook modes and a separate
ABI 3 floor. Use separate installed/bound configurations and separate harness
invocations when a different kernel or host policy is required. Each invocation
records its measured cells; one invocation does not claim the full matrix.
The case records its own measured `restriction`, `abi`, `kernel`, and
`bwrap_version`, and checks the live sysctl/kernel probe against each cell. Profile
installation and restriction-on unprofiled controls belong to admin acceptance.

The component preparation in [test-box.md](test-box.md) compares bwrap with
`unshare --user --map-root-user --mount -- /usr/bin/true` before and after the
bwrap-only profile is installed. The unprofiled control requires capabilities
inside the new user namespace and must remain denied. Bare user namespace
creation may succeed under Ubuntu's restriction and is not a refusal control.
The canary's separate `unshare(0)` operation tests seccomp denial instead.
Root namespace preparation uses only the administrator entry's `--install`
then `--check` modes, retaining their private receipts and unchanged sysctls.

The outside human coordinator supplies a fresh private
`test_root/authority/NNNNNN.proof.json` for every numbered CLI invocation.
Read calls use a proof for `human.session`, which the shared CLI establishes on
the same connection as the requested read. Root spawn uses `--session-proof`;
other mutations use their exact operation proof. The authority directory is
0700 and proof files are ordinary 0600 files. Missing authority retains a typed
`prerequisite_missing` owner wait and stops before the CLI. A copied session ID
or an elapsed wait never supplies human authority.

The observer first proves the outside file exists, is world-readable and has
the expected independently generated hash. It reads that same file again after
the canary and after stop. Canary results contain actual errno values, never
pass/fail decisions. Successful own-work, Git, temp, mmap, link, loopback and
own-signal controls must accompany the denied operations. The outside observer
checks marker-bearing processes' kernel start times after stop, independently
of the service's survivor count. It checks their kernel UID/groups and actual
cgroup membership, then requires empty `cgroup.procs` and `populated 0` after
stop. The cgroup lease remains until collection. Observer read-back compares
bytes, inode, mode, owner, link count, mtime and ctime; access time is excluded
because observation itself reads files. Unknown observation cannot pass. It
archives, marks the disposable lane abandoned, and cleans through the CLI,
then verifies both the retained cleaned status and the removed worktree.
Collection obtains the actual `lane review` receipt before `lane mark`; an empty
review object is invalid under the shared strict decoder. The retained real
vendor session must also have the draft.3 `history_id`.

The same stop/observation/collection route runs in finally after a reached red
assertion or another exception. An independent fresh-UID inventory catches
the detached grandchild even when a cgroup red has lost containment. pidfds
bind signals to actual PID/start-time/UID identities, and cleanup retains its
before/after OS facts. A failed or unknown collection is reported as such; it
is not promoted to a successful receipt. A start with no recoverable target
remains unknown and is retained for supervisor reconciliation.

All succeeded denial names are retained in deterministic order, so a second
successful boundary cannot hide the mutation's targeted observation. Timeouts
in filesystem, FD, signal or syscall controls are unexplained failures. Only
the four observed Internet socket controls may time out, and only with zero
outside connections/packets/bytes. UDP send completion is recorded separately
from receive status; outside listeners intentionally do not echo datagrams.
Any received datagram fails the boundary even if the canary's receive times out.

After clean, the case reads the actual helper.released event for that life/run
and clean operation. It requires the draft.4 ReleaseReceipt, its original
process/containment binding, actual operation/effect identity, measurement time
and known-zero survivors/connections/jobs/writable exports. A cleaned status or
the caller's zero cannot substitute for that helper receipt. The independent
kernel process/cgroup and outside-file observations remain required as well.

Required red artifacts remove one boundary at a time: broad-root mount,
writable nested target, inherited FD, absent Landlock, absent network denial,
absent cgroup containment, and false zero-survivors observation. Supply a
`mutation_id` matching the altered artifact and retain its bytes. Every red
run must fail at a reached syscall/read-back/survivor assertion. Missing
prerequisites must refuse before creating the agent marker; that is a separate
negative cell, not a substitute for a boundary red run.
The exact public IDs, required failure observations and file-backed component
pair runner are documented in [MUTATIONS.md](MUTATIONS.md). A red failure at an
unrelated later step is recorded as unreached for that mutation.

Draft.4 supplies measured ReleaseReceipt and causal HelperControl requests.
The public launcher now registers/resolves/prepares through that helper,
verifies the committed BindLaunch tuple, reconciles before opening, observes
the returned process and checks stop/abort/release receipts. It requires a
service-owned ControlSource construction dependency for actual retained spec,
effect and binding context. Assembly currently supplies no such adapter; the
helper's installed gate/runtime implementation also remains a separate admin
dependency. Those calls fail explicitly. The Linux package's CONTRACT-GAPS.md
names the owners and exact adapter obligations. Unit namespace tests cannot
close this installed public gate.
