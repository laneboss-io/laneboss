# Installed SERVE-STATE acceptance

Acceptance is exclusively the composed serve E2E through the installed CLI and
Unix socket. It must fail on the base for the intended reason and pass on the
candidate. Both artifacts, source inputs, hashes, commands, exit codes, native
observations and collection evidence must be retained. Unit suites, static
checks, an unavailable prerequisite or a generic nonzero exit cannot replace
that comparison.

Run only on the supervisor's disposable Linux machine. The harness supplies
absolute context/result paths and the actual installed binary. It must launch
the service case as a genuinely enrolled lane in its real boundary, with a
protected binding and independent controller. Do not guess a service unit,
start a model request, lend the lane direct state access or use constructor
fixtures to make a row pass.

The current driver implements an installed prefix: artifact/binding and ready
Health checks; upload/chunk/commit/read of unpredictable bytes; dropping an append
reply and observing its record through an authorized CLI query; controller
restart; exact same-key retry; changed-key refusal with unchanged visible
record; a real read head; and unknown-field/schema/SCM_RIGHTS refusals.
It explicitly stops at the unresolved request-scoped cardinality gate.
Its full result remains failing/unreached, with later rows not_run.

The completed case must measure all of the following:

1. Actual authorized upload/append/read through the installed artifact and
   native transport, including scoped visibility and real response head.
2. Lost reply, real service restart and exact retry under the same authentic
   life, principal, configuration and key. Require exactly one durable receipt,
   event and intended observable effect, with original result bytes. Resolve the
   zero-outbox records.append catalog issue without inventing an effect.
3. Real read/write opens of known DB, WAL and journal canaries from the lane,
   with kernel denial and working scoped RPC as the opposite control. The same
   confined launch must inspect inherited FDs. A nonexistent file is not denial.
4. Duplicate/unknown members, wrong schema, UTF-8/null/bounds/truncation and
   descriptor-bearing inputs must refuse without state mutation. Missing/mixed
   per-fragment writer evidence and a real inherited-socket writer must fail.
5. Stop consuming a genuine event subscription, exceed the frame/byte bound,
   observe an explicit resumable error, and keep a concurrent control operation
   within its deadline. Resume from the last delivered cursor and account for
   every authorized event. EOF is not an authentic selected end.
6. During a real controlled service outage, the same installed read/mutation
   must return typed unavailable and never open or alter direct state. Record
   actual process/descriptor/resource collection without guessed zero counts.

Each deliberate red must reach its target assertion; setup/compile failures,
skips, constant replies, swallowed failures and unrelated errors grant no
credit. Preserve failed evidence and stop the dependent phase.

The supervisor runs the composed case:

```sh
bash e2e/v2/cases/serve/run.sh --context /test/cases/serve/context.json --result /test/cases/serve/result.json
```

The service subcase entry is:

```sh
bash e2e/v2/cases/service/run.sh --context /test/cases/service/context.json --result /test/cases/service/result.json
```
