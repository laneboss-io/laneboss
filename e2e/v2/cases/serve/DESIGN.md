# Installed caller and lifecycle design

The administrator helper, service, identity, store, grant resolver, worker and
native isolation remain the real implementations. Only the unavailable hardware
authenticator and vendor executables are explicit test fixtures. Neither fixture
supplies product authority, proof, ticket, committed object or process observation.

Software authentication uses real WebAuthn create/packed self-attestation and
P-256 signed get assertions. Shared API constants define the public device markers
and production rejection. The actual store already checks the complete inventory
before listening; assembly delegates to that existing check by using store.New.
Private signing state never enters the checkout, runtime or evidence archives.
Every dependent row retains simulated presence and unproven human approval.

The driver obtains every proof/session/ticket through the installed CLI. Reads use
a fresh human.session proof on the read's own connection. Controls use exact
operation-bound proofs and the current generation. Missing protected installer
metadata remains an owner request; no origin, endpoint, UID or selector is guessed.
The current identity credential selector/receipt handback needs agreement before
the software device's later assertions can complete the real enrollment flow.

The two L5 roots select actual approved project/profile/task inputs. Their vendor
fixture plan uses the pinned immutable runtime object at its fixed namespace path,
the supplied run/session/home/history/prompt/slot and /work/main. It leaves base
environment projection to the real helper. Only the real lifecycle planner,
identity commit, native gate and installed service can release that process.
The fixture's CLI calls and metadata are evidence to inspect, not native authority.

Native LaneCheck and actual lifecycle events must correlate the original run,
launch and containment. Stop reason bytes are uploaded and committed. A successful
operation alone does not prove running or terminal quiescence. The driver requires
measured positive survivors before stop and a known terminal exit/signal with zero
survivors afterward, then abandons, archives and cleans through real service ports.
It never requests accepted/merged or invents a review/archive receipt.

The store resource wrapper embeds the concrete implementation so its private
commit/replay and launch-control/recovery methods remain visible to consumers.
Real constructors initialize the production dependency graph. A constructor
error stops assembly; no zero-value module fallback is constructed. Missing materialization and native credential/endpoint projection
ports keep their typed owner failures. Unenrolled real runners do not become
stand-ins. Both test tags and protected dual-driver enrollment are required for
fixture planning. Production retains credential and operation-readiness refusals.
The installed native backend receives the actual wall clock. Module registration
can complete before unfinished operations are used. Installed policy/vendor
constructors validate stable ports at startup and defer only operation-specific
enrollment to strict call-time checks. STARTUP.md describes the production graph
test, which requires an actual untagged installed artifact and no fixture runtime.

The shared step catalog defines every required observation independently of the
report's claimed list. Stored refusals, missing rows, unexecuted claims and lost
simulation provenance fail summary validation. Cleanup preserves the original
failure and never retries a refused control through another route. Stopping a unit
cannot credit an uncollected lane. The independent state scope also retains its
unmet capture/workspace/restart/count gates and requires a real judge projection.

All runtime and mutation evidence must come from the authorized Linux box. Static
checks on this Mac do not establish installed acceptance or authenticated AI usage.
