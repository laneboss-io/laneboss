## Protected publication before the first lane

Default installed mode assembles an explicit test-org bundle in the harness's
protected install-input step. scripts/v2-serve/README documents the shipped
source bytes, bounded grants, validator calls and exact retained inputs. The
standalone assembler is never linked into or called by the installed product.
The box suite needs no added arguments. It receives no pass credit until the
real installer/publisher and subsequent reads accept those exact bytes.

The harness also accepts --config and --boot together. --boot names the exact
administrator boot input described by the administrator README. The additional
required fields are admin_enrollment, launch_enrollment,
launch_enrollment_file, initial_publication, initial_publication_file and
initial_objects. It consumes the supplied runtime and publication unchanged.
This explicit mode consumes policy, source, L5 role, task and profile bytes
unchanged. Neither mode generates a publication receipt. Missing or rejected
inputs stop the gate and all dependent rows remain failed/unrun.

Every supplied descriptor and declared object is read from its root-owned,
single-link protected file, with no linked/shared-writable ancestor. Initial
files require 0444. Exact raw hashes and byte counts must agree with all
references; the supplied runtime pins must match the binaries actually built
by this case. Both builds use trimpath so a protected bundle can be prepared
against the same source, dependencies, tags and toolchain before invocation.
The test fixture descriptor and test task are supplied bytes too. The native
key stays only in its protected input and the private installed key store.
Public source/runtime/publication bytes and native input metadata are retained.

Installation must report publication=pending. The harness verifies the installed
runtime, launch reference, RP policy and immutable descriptor against its exact
input. After genuine registration, it calls the real installer --publish twice,
using new protected evidence directories. Both calls must return the same
durable receipt. Each response must select the supplied publication ID and
manifest, the exact initial operation and event IDs, a positive committed
sequence and generation one. The marker has the reserved receipt ID for this
configuration and a real bounded content pin.

The fixed initial_publish method now passes through the same authenticated root
daemon as begin/complete. The composed service listener decodes InitialRequest
and calls PublishInitialFrame with its actual Connection and Frame. The
publication context repeats the native unit, writer, lifetime, installed bytes,
endpoint and installation checks. It never opens the root helper's procfs
executable from the service UID. The root daemon retains its mapped-artifact
checks on itself and the external root CLI. Service callers still cannot relay
administrator operations, and root relay callers cannot run service operations.

The existing real Transact remains the sole publication writer. Three narrow
store connections now let its read-back finish: OrgSnapshot reads the actual
current org projection and requires the requested generation; internal service
Events can read configuration events without a fabricated life/run; and event
validation recognizes the administrator's exact initial marker payload while
preserving the ordinary ConfigView bootstrap form. Public event reads still
require a real selected life/run. Source, TemplateSources and BriefingInput
are still separate service-owner ports.

The publisher requests Events with Since equal to its operation's first
sequence minus one. It requires the first returned event to match kind,
configuration, event ID, operation ID, exact sequence and marker bytes. It does
not search for any convenient later event. The service additionally rereads
the marker metadata/bytes, policy, snapshot, descriptor and every object before
returning a receipt. The harness then uses genuine human-session reads to
check the marker, exact descriptor and policy bytes, and operation with
first_seq=last_seq=committed_seq. Its public stream is never used to pretend
that an unselected org event query exists. Current typed policy/snapshot
verification belongs to the native publisher's durable read-back. policy.get
also needs the still-unmerged Source port, so it is not used as a substitute.

Default mode supplies a protected RootGrantRequest and both driver StartRequest
proposals from the same bundle. After actual grants.root succeeds, it matches
the returned data/profile scope to the approved bytes and binds only the real
issued member IDs. The --root-grants and --lane-inputs alternatives remain exact
external requests. Their L5 role, task, policy generation, project and driver
must select the actual initial publication. Neither a caller-uploaded document
nor the presence of a profile selector issues a grant. The root capability

that is already closed or cannot write can only retain its journal diagnostic;

The helper unit's 0077 umask previously left newly created control directories
potentially 0700. The helper now explicitly sets its root-owned control directory
to 0755 after checking its protected path. Its process inventory remains root-owned
and not group/world writable. This exposes read/traverse facts, not cgroup write
authority. No ptrace capability or privilege is added to the service.

Another ordinary process cannot satisfy the unit, sole-PID, protected socket,
installed-byte and native lifetime/writer checks by claiming UID/config metadata.
A non-helper root executable also fails the daemon's mapped-artifact check before
it can request forwarding. Host administrators remain the trust root for protected
units, cgroups and installed files; replacing those is administrative authority,
not an application peer capability. There is no UID-only or alternate root path.
Runtime canaries and the full positive installed path remain required on Linux.

The helper path refusal also covers protected input data. runEnrollment first
loads the administrator binding and installed artifact, reads the service and
human binding files, pins its executing artifact, then calls readProtected on
the request file. protectedPath walks every component with no-follow metadata
checks; readProtected separately requires a regular single-link leaf. Unlinked
means no symlink component. Regular files require link count 1; directories may
have their normal directory link counts.

The installer writes the executable below /usr/lib/laneboss-v2, in its version
directory, as root-owned mode 0555 with one link. Its publication link is removed
from the temporary name before read-back. It creates version directories as
root-owned 0755 and requires existing ancestors to be root-owned and not shared
writable. The check uses that installed path, not the build executable.

a single-link regular 0600 input. The product guard and installer are unchanged.
No shared directory is chmodded and no refused check is bypassed.
